# Major Feats

- <b>Role assignment (ACPs) during project creation: </b> Now you can declare role-to-member assignments directly in the Project DSL model using the new `roles` attribute, so Access Control Policies (ACPs) are created and synced from your DSL file without a separate `calm create acp` call (Although `calm create acp` command still works). Map a role name to a list of user/group references; a user or group can be assigned to only one role (validated at compile time) in a single project, while in other projects a user can have different role. And one role can have multiple users and/or groups. <b>To add a user/user-group in a project during project creation it is now mandatory to specify it's role</b>. Without role user/user-group will not be added. Refer to the example below or follow guide [here](https://www.nutanix.dev/docs/self-service-dsl/getting-started/projects/#assigning-role-to-user-during-project-creation-from-dsl-v440)

  ```python
  class MyProject(Project):
      users = [Ref.User(name="alice"), Ref.User(name="bob")]
      groups = [Ref.Group(name="dev-team")]

      roles = {
          "Developer": [users[0], groups[0]],
          "Operator": [users[1]],
      }
  ```

- <b>New Macro support in AHV VM spec: </b> Now you can drive AHV VM spec fields with runtime macros (`@@{...}@@`) so a single blueprint can be launched with different VM configurations and power custom forms. Refer to the working example [here](https://github.com/nutanix/calm-dsl/blob/master/examples/AHV_MACRO_BLUEPRINT/ahv_macro_blueprint.py) and guide [here](https://www.nutanix.dev/docs/self-service-dsl/getting-started/blueprints/#custom-forms-and-macro-support-in-ahv-blueprints-calm-440), [models](https://www.nutanix.dev/docs/self-service-dsl/models/Substrate/#ahv-substrate-macro-support-calm-440)

  The following AHV fields can be macro'd:

  | Field | Type | DSL Path |
  |---|---|---|
  | VM Name | String | `AhvVm.name` |
  | vCPUs (Sockets) | Int | `AhvVmResources.num_sockets` |
  | Cores per vCPU | Int | `AhvVmResources.num_vcpus_per_socket` |
  | Memory (MiB) | Int | `AhvVmResources.memory_size_mib` |
  | VM Power State | String | `AhvVmResources.power_state` |
  | Cluster Reference | JSON | `AhvVm.cluster_reference` |
  | Disk Image | JSON | `AhvDisk.data_source_reference` |
  | Disk Size (MiB) | Int | `AhvDisk.disk_size_mib` |
  | NIC (whole item) | JSON | `AhvVmResources.nic_list[i]` |
  | Categories | JSON | `AhvVm.categories` |
  | Guest Customization | JSON | `AhvVmResources.guest_customization` |

- <b>Revert (in-place restore) for AHV VMs: </b> Now you can revert an AHV VM to a recovery point in place. Set the in-place restore flag on the snapshot restore configuration in your AHV blueprint. As a VM and its recovery point must reside on the same cluster for a revert, DSL now validates at compile time and does not allow `revert` as the restore type when the snapshot location is a remote cluster. Read more [here](https://www.nutanix.dev/docs/self-service-dsl/getting-started/policy/protection-policy/#restore-types-clone-vs-in-place-restore-revert) and [models](https://www.nutanix.dev/docs/self-service-dsl/models/ProtectionPolicy/#restore-config)

# Improvements

- <b>Keyword search based category filter: </b> Now you can search for a category using a keyword (phrase) for AHV provider resource. `calm create provider_spec -t AHV_VM` prompts are now more intelligent and lets you type a keyword to filter categories of your choice. Additionally you can use this keyword based search during launch of blueprint if categories are runtime editable.

- <b>The Global Variables and Library task can also be associated to the system-defined Default Project which is aliased as '_internal' in the code: </b> With Projects 2.0, `_internal` projects can now be set as the owner project for a Global Variable or a Library Task through DSL by passing `_internal` in the project metadata. 

- <b>Share/Unshare projects with Library Task</b>: Library Tasks can also be shared/unshared across projects with the new commands `calm share library task "<Task Name>" -p <project1> -p <project2>` and `calm unshare library task "<Task Name>" -p <project1> -p <project2>`.

- <b>Larger DSL cache: </b> The DSL cache now stores more than 250 entries per entity when they are present during a cache sync, so large environments no longer silently drop entities from the cache.

- <b>`calm init runbook` generates Python 3 scripts: </b> Scripts generated by `calm init runbook` are now Python 3 instead of Python 2.

- <b>Deprecation of custom ACP names in create call: </b> Creating an ACP with a custom name is now deprecated; the create call issues a deprecation warning as custom ACP names are no longer allowed.

# Bug Fixes

- Fixed NIC runtime editables to use the correct Nutanix account (resolved from the substrate's PE) when a project has multiple accounts, instead of always using the first registered account.
- Fixed old/new host mismatch validation error for NCM 2.0+ setups 
- NCM detection improved and no longer syncs/stores PC version for NCM 2.0+ setups.


# Known issues

- Project update/delete fails if a subnet is shared with multiple projects. Navigate to known issues section in Nutanix Projects documentation [here](https://portal.nutanix.com/page/documents/details?targetId=Release-Notes-Projects-vpc7_6:top-rel-projects-known-issues-r.html) also read KB-22167, KB-22206 for more details.
- The `--name` flag doesn't work with the `calm get vm-recovery-points` command. While filtering recovery points by name is not available, you can still retrieve all recovery points for a project and manually search for a specific one as needed.
